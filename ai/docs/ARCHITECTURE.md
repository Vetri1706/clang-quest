# Architecture and operational specification for a raw NumPy language-model framework

## 1. Purpose, evidence, and system boundary

This document specifies an inspectable language-model framework whose differentiation, architecture, optimization, tokenization, and distributed messages are implemented directly with NumPy and the Python standard library. It is intended to make mathematical and systems assumptions visible. It is not a claim that a short development exercise has produced a certified production platform or a useful seven-billion-parameter language model. Those claims require workload testing, operational experience, independent assessment, and substantial training resources that are not supplied by source code alone.

The system includes a dense decoder using Multi-Head Latent Attention, rotary position embeddings, RMS normalization, and SwiGLU feed-forward transformations. Its large configuration describes 7,018,450,944 parameters, while local execution uses small configurations of the same architecture. The distinction is fundamental: an exact parameter inventory establishes the shape of a model, not the feasibility of training it on the machine performing validation. Allocation guards prevent an accidental large-model initialization during a metadata inspection.

The numerical backend is NumPy. Matrix multiplication may internally call the BLAS implementation distributed with NumPy; that is consistent with using NumPy, but differs from writing architecture-specific assembly. The reference tiled multiplication and attention algorithms expose their reductions in Python and array operations. No external automatic differentiation, model architecture, tokenizer, optimizer, or distributed-training package is imported. Reduced precision is explicitly emulated, and socket experiments are explicitly local simulations.

The evidence attached to this project consists of mathematical derivations, finite-difference checks, equivalence tests, failure tests, actual small optimizer updates, and machine-readable distributed reports. Each is useful for a different proposition. A gradient check establishes a local numerical property. A successful TCP test establishes behavior under a particular schedule. Neither establishes general reasoning capability, hardware throughput, or resilience under arbitrary failures.

## 2. Component structure and ownership

The package separates the tensor graph from low-level numerical kernels. A tensor owns its primal array, gradient flag, graph parents, backward closure, and optional accumulated leaf gradient. Kernel routines implement numerical contractions and normalization without relying on another differentiator. This arrangement keeps custom analytical attention derivatives testable independently of the rest of the decoder, while ordinary compositions reuse the same reverse-mode machinery.

The model module owns a deterministic mapping from parameter names to tensors. Names are stable across initialization, optimization, and checkpoint restoration. Tied embeddings appear once in this mapping; their graph receives contributions from both input lookup and output projection. This avoids a common failure in which an optimizer updates the same storage twice because it is reachable through two module paths. Shape metadata can be inspected without constructing parameter arrays.

The cache module owns physical latent pages and logical sequence tables. The data module owns document boundaries, shifted targets, and supervision masks. The optimizer owns master weights, moments, update counters, and precision-scaling state. Checkpoint manifests connect these states to the tokenizer and source-data digest. The tokenizer has an independent, versioned JSON representation, so changing token IDs cannot be mistaken for a harmless change to preprocessing.

Networking is organized around a bounded coordinator and explicit process groups. A process group identifies a rank and ordered membership set; collectives are operations on that set, not global side effects inferred from timing. The parameter-server API is a separate synchronization model, and sharded optimization is a separate ownership model. Their coexistence does not imply that they should all be used for every workload. The executable scripts expose which combination is actually being exercised, and reports identify the model, topology, and reference comparison used by each run.

## 3. Tensor graph semantics and differentiation

Reverse-mode differentiation is a graph traversal over operations already executed during the forward pass. Each operation records enough information to compute a vector–Jacobian product when its output cotangent becomes available. The engine constructs an iterative topological order, then walks it backward. Contributions from multiple uses of the same parent are added before that parent is processed. This handles residual connections, tied embeddings, and parameters used in more than one microbatch.

Broadcasting requires particular care. A forward multiplication can expand a singleton dimension without allocating a full independent parameter. Its backward operation must sum all expanded uses back into the original shape. Vector matrix products require temporary promotion and later removal of singleton axes. Gather operations require scatter-add; ordinary indexed assignment would lose repeated token contributions. These details are part of the tensor contract and receive targeted tests rather than being left to numerical coincidence.

The engine accumulates gradients on leaves. Intermediate cotangents are temporary unless explicitly retained, reducing the amount of gradient storage after backward. This does not eliminate retained forward activations: graph closures still need values required by their derivatives. A no-gradient context disables graph construction for reference-model evaluation and inference, where retaining those relationships would waste memory. The context is process-local; it is not a substitute for a distributed gradient protocol.

Mutation between forward and backward is outside the intended execution contract. Parameters are updated only after all microbatch backward passes for the optimizer attempt have completed. Checkpointing is performed after gradients have been cleared in the provided loop, although the checkpoint format can preserve gradients for a caller implementing a mid-accumulation snapshot. Finite-difference tests perturb selected entries in float64 and compare analytical derivatives with central differences. This validates representative operations and paths, while acknowledging that finite samples are not a proof over every possible input.

## 4. Decoder architecture and parameter inventory

The large preset has vocabulary size 32,000, model width 4,096, thirty-two decoder blocks, and thirty-two attention heads. The query compression rank is 1,536 and the key/value compression rank is 512. Each head has 128 content coordinates, 64 rotary coordinates, and 128 value coordinates. The feed-forward hidden width is 14,336. Its default context limit is 32,768 tokens, although the context limit is a configuration constraint rather than an assertion that local execution at that length is practical.

Every block first normalizes its input for attention. The attention branch compresses queries and key/value information, applies latent normalizations, reconstructs head-specific content coordinates, and combines them with decoupled rotary coordinates. Attention output is projected back into model width and added through a residual connection. A second normalization feeds separate gate and value projections. The SiLU-transformed gate multiplies the value branch elementwise before the down projection and second residual addition.

The parameter inventory counts every normalization scale, compression projection, reconstruction projection, output projection, feed-forward matrix, and embedding table. The default language-model output shares the embedding matrix, so that matrix is counted once. An untied output projection is available and is useful when demonstrating stage-separated embeddings and heads. The inventory and allocated parameter count are tested against each other in small configurations. The large count is checked before an allocation path can reach the random-number generator.

The architecture is inspired by low-rank attention designs, but it is deliberately a dense model rather than a reproduction of an external mixture-of-experts implementation. There is no hidden expert router, auxiliary load-balancing loss, or imported pretrained checkpoint. The code begins with random weights. A configuration resembling a large research model does not inherit that model's dataset, tokenizer quality, instruction following, or benchmark results.

## 5. Attention computation and working memory

Attention computes the exact masked softmax function using an online normalization recurrence. Query and key/value tiles are processed while retaining a row maximum, an exponential denominator, and an output accumulator. When a newly visited tile raises the maximum, earlier accumulated quantities are rescaled into the new numerical frame. This avoids constructing the full probability matrix merely to normalize each row. Causal offsets and explicit boolean masks are applied before probability contributions are accumulated.

Backward reconstructs local probability tiles from saved normalization statistics. It uses the identity relating the softmax row reduction to the inner product between output and output gradient. Query, key, and value gradients are accumulated from those reconstructed tiles. The full sequence-by-sequence probability matrix is never a retained activation of this operation. Fully masked rows are defined to produce zero output and zero gradients, preventing invalid infinite-subtraction expressions from contaminating otherwise valid examples.

This implementation follows the mathematics of IO-aware tiled attention. It does not place tiles in accelerator shared memory, fuse exponentiation with matrix instructions, schedule asynchronous transfers, or exploit architecture-specific tensor cores. Python dispatch, NumPy temporaries, and BLAS calls have different performance characteristics. Calling the algorithm tiled exact attention is supported by its numerical behavior; calling it an optimized GPU FlashAttention kernel would be unsupported.

The packing layer currently materializes a boolean attention mask whose size is quadratic in sequence length. That mask can dominate memory even when the attention kernel avoids a quadratic floating-point probability matrix. Consequently, the complete framework does not have purely linear sequence memory in every configuration. A capacity estimate must count the mask separately. For extremely long contexts, a production implementation would need a structural mask interface or block schedule that represents document boundaries without constructing every pairwise permission bit. That extension is not silently assumed in the current measurements.

## 6. Latent paging, sharing, and transactional failure

Autoregressive decoding stores compressed key/value latents and rotary keys rather than persistent expanded keys and values for every head. The key up-projection is algebraically absorbed into the current query. Attention then scores the compressed cache directly, accumulates a latent context, and applies the value up-projection after the weighted sum. This transformation is tested against ordinary full-sequence forward execution, including multiple physical page boundaries.

A logical sequence owns a list of physical page identifiers and a valid token count. A token position selects a logical page by integer division and an offset by remainder. The page pool is allocated once with a fixed page size, page count, dtype, and byte limit. Exhaustion raises an explicit error. It does not silently discard an active sequence, allocate unbounded extra storage, or reuse a live page. Releasing the last reference clears a page before returning it to the free list.

Prefix sharing copies the logical page table and increments physical reference counts. A later append to a shared partial page triggers copy-on-write, while appending after a full page allocates another page. Only valid token counts are exposed to attention. Unused trailing slots never become keys simply because memory exists for them. This is essential when branches have different lengths or a previously longer allocation is reused.

A decode reservation is treated as a small transaction. If a later layer fails, rollback restores the previous table, length, reference counts, and free-page capacity. Tests include failure after copy-on-write with several sharing branches, not only failure at a fresh page boundary. Cached decoding currently executes in full working precision; it rejects a model marked for emulated reduced precision so that callers cannot receive a silently different numerical path. Concurrent cache mutation from several threads is not implemented. The delivered serving layer gives each request an independent cache and accounts for all active cache arrays under a shared admission lock. It never shares mutable cache objects across request threads.

## 7. Tokenization, corpus streaming, and packing

The tokenizer starts from a byte vocabulary and reserved control tokens, then learns byte-pair merges from a bounded amount of original text. Pair counts and deterministic tie-breaking produce a reproducible merge order. Encoding repeatedly applies the best-ranked available merge. The byte basis ensures that arbitrary UTF-8 input has a representation without an unknown-word fallback. Decoding reconstructs bytes and handles control tokens according to an explicit option.

Tokenizer training is complete but intentionally simple. It retains a bounded training sample, represented through Python containers whose overhead exceeds the raw byte count. Repeated pair scans cost time proportional to the number of merges and retained tokens. This is not a memory-free or industrial-throughput BPE trainer. The maximum raw-byte argument is a sample bound, not a total process-memory guarantee. Encoding a very large individual document also requires its token representation to exist while that document is packed.

The text reader uses an incremental UTF-8 decoder over bounded byte chunks and supports compressed input. Plain-text chunks are treated as separate packing documents, making that boundary policy explicit. JSONL preserves each record as a document but rejects records over a configured line-size limit. The reader can traverse multi-gigabyte files without loading the complete file, although no multi-gigabyte throughput result is claimed from the small bundled fixtures.

Packing retains a window plus one lookahead token. The lookahead becomes the next window's first context token, preserving next-token transitions without duplicating supervised targets. Segment identifiers separate documents. Attention permits only causal positions within the same real segment, and padding has an explicit convention. Loss masks suppress transitions between documents and padding targets. SFT encodes prompt and response separately so that a merge cannot straddle their supervision boundary. Prompt-only windows may exist; the training loop skips them rather than dividing by a zero target count. DPO rejects overlong pairs instead of silently truncating one completion and changing the preference comparison.

## 8. Precision emulation and optimizer arithmetic

Model parameters use float32 or float64 storage. Integer dtypes are rejected before initialization so that a byte-limit check cannot be bypassed by requesting integer storage that a later layer promotes. Reduced-precision experiments round values to FP16 or BF16 representations and then return them to float32 arrays for computation. BF16 rounding uses a retained least-significant-bit correction for round-to-nearest, ties-to-even. A straight-through estimator supplies the gradient through the rounding operation.

This procedure emulates rounding behavior; it does not reproduce every hardware instruction, accumulation mode, denormal rule, or fused rounding boundary. It also does not provide the memory savings of storing all intermediates in native two-byte buffers. Projections quantize relevant operands and projected activations, while normalization and softmax retain stable working reductions. Numerical and throughput claims must therefore distinguish emulated reduced precision from a native accelerator mixed-precision implementation.

AdamW owns float32 master parameters and first and second moments. Each active parameter has an update counter for bias correction. Weight decay is decoupled from the gradient term, so it is applied directly to the master parameter. Tied parameter objects are rejected if supplied twice to the optimizer. Before any update, all active gradients are validated. Candidate moments, master weights, and cast visible parameters are then computed separately and checked together before commit. This prevents an early parameter from changing before a later finite gradient overflows its squared moment. The transactional candidate arrays add approximately sixteen bytes per active parameter when visible storage is float32, plus per-operation arithmetic workspace; this memory is separate from persistent state.

Loss scaling multiplies microbatch losses before backward, then unscales accumulated gradients before clipping and updating. A nonfinite gradient causes the complete attempt to be skipped and the scale to decrease. Forward overflow is a different failure: lowering the loss scale cannot make an unrepresentable activation finite. The model raises a specific floating-point error for that case; the loop clears partial gradients, saves unchanged valid weights and counters, and stops rather than retrying indefinitely. Tests verify this behavior after an earlier microbatch has already contributed gradients.

## 9. Training phases and objective normalization

Pretraining uses causal next-token prediction on packed documents. SFT uses the same decoder and attention machinery, but the target mask restricts the objective to response tokens and the response terminator. Each microbatch's mean loss is weighted by its supervised-token count before accumulation. Dividing the summed token losses by the total target count yields the same gradient as a combined batch, even when response lengths differ substantially.

DPO evaluates preferred and rejected responses under the current policy and a frozen reference. Both sequence scores sum only response log-probabilities. The difference between policy log-odds and reference log-odds is scaled by beta and passed through a stable negative-log-sigmoid objective. The reference graph is disabled and the reference parameters are preserved independently. Preference pairs are equally weighted in the provided loop; this policy is distinct from weighting every response token equally across pairs.

A phase can initialize from a previous run's model and tokenizer while starting a fresh optimizer. This makes a pretraining-to-SFT-to-DPO experiment explicit. Resuming a phase instead restores optimizer moments, random state, loss scale, counters, and deterministic data position. Those two actions are not interchangeable. Reusing an old optimizer unintentionally across a changed objective can produce a materially different experiment, while resetting moments during a claimed exact resume breaks continuity.

The bundled updates are correctness exercises on small original fixtures. Their purpose is to prove that data flow, gradients, updates, and snapshots connect end to end. A decreasing fixture loss is not evidence that the model has learned programming reliably. No final validation set is fed into optimizer updates, and no source silently downloads a pretrained model. The model remains randomly initialized unless a caller explicitly initializes a later phase from a checkpoint created by this framework.

The automatic ZeRO corpus path now trains on actual text and response-masked SFT data. It stages an immutable bounded source copy and learns its byte-pair merges from that source. Every rank replays a common global stream but selects disjoint sample positions. Because gradient reduce-scatter averages ranks, each local summed-token loss is multiplied by data degree divided by global supervised-token count. This produces the same update as a dense global token objective even when response masks differ. Checkpoint metadata binds the replay position to source, tokenizer, configuration, and settings hashes. Tests prove exact continuation across new processes and verify unequal target mass against the dense reference. This corpus path has no DPO or dense serving-format export, and its strict local staging bound is distinct from the larger-file capability of the streaming library.

## 10. Checkpoint consistency and recovery

A checkpoint commits an immutable NumPy payload and a manifest referencing that payload. The payload is written and synchronized before the manifest is atomically replaced. The manifest includes parameter names, optimizer metadata, random-generator state, counters, scaler state, and a checksum. Loading prohibits pickle, validates array shapes and parameter ownership, and checks the payload digest before applying state. This design avoids treating an incomplete write as a committed checkpoint.

The manifest is the commit point. An older immutable payload may remain after a later commit, and an interrupted write may leave an unreferenced payload. Retention and cleanup are operational responsibilities; blindly deleting all but the newest file by timestamp could remove the payload actually referenced by a valid manifest. Disk budgets must account for retained snapshots. The local trainer holds a kernel-backed advisory run lock, preventing concurrent cooperating writers. A separate distributed checkpoint module coordinates immutable per-rank preparation and one shared-filesystem manifest commit. It does not implement distributed object storage or a consensus protocol tolerant of a failed coordinator.

Recovery verifies the source-data digest and tokenizer digest. Restoring weights while changing the token mapping would be numerically well-formed but semantically invalid, which is why tokenizer integrity is part of recovery rather than an optional convenience. The deterministic stream replays previously consumed packed examples to recover its position. This preserves bounded memory and exact behavior for unchanged inputs, but replay can be expensive for long-running multi-gigabyte jobs; it is not a constant-time seek index.

Checksums detect accidental corruption, not authenticity against an attacker who can replace both payload and manifest. Checkpoint directories remain trusted local inputs. Artifact loading now preflights central-directory entry counts and sizes, uncompressed byte extents, and bounded NPY headers before allocation. It rejects duplicate ZIP names, object dtypes, symbolic-link files, invalid topology scalars, negative second moments, and nonfinite JSON exponents. Authenticated manifests, external provenance controls, and an operational retention policy remain separate requirements. Exact recovery tests compare parameters, moments, logs, and frozen references between uninterrupted and interrupted execution, rather than merely checking that a checkpoint file can be opened.

## 11. Raw TCP transport and the failure model

The distributed transport uses explicit frames rather than relying on TCP write boundaries. A fixed network-order header specifies metadata length and raw array payload length. JSON metadata identifies operations, shapes, dtypes, participants, and sequence information. Array values travel as contiguous bytes. The receiver verifies the declared extents against the actual payload before constructing an array view. Network messages never invoke pickle or execute serialized Python objects.

Each connection authenticates frames with HMAC-SHA256 and independent monotonic sequence counters for each direction. A freshly generated per-run token is supplied to the spawned workers. This detects modification and rejects replay within the connection protocol. It does not encrypt data, isolate mutually untrusted workers holding the same secret, or make the coordinator untrusted. The coordinator can observe gradients and parameters. Default binding is loopback, and public exposure is outside the intended deployment boundary.

The protocol sets finite metadata, payload, aggregate collective, and queued-message limits. Deadlines apply to missing participants and blocked operations. Dtype allowlists exclude object arrays, and shapes must have valid nonnegative extents whose byte product matches the frame. A malformed frame, mismatched collective, disconnected participant, or expired deadline aborts the session. The parent terminates surviving workers rather than allowing a partial optimizer update to masquerade as a successful distributed step.

This failure model is fail-stop recovery from a checkpoint, not elastic membership or Byzantine tolerance. A production deployment would need an authenticated encrypted private transport, credential rotation, admission control, metrics, durable scheduling, and a documented restart policy. HMAC is one integrity layer, not a comprehensive security architecture. Tests deliberately tamper with frames, sequences, dtypes, extents, authentication, and collective shapes to establish the behavior of the implemented layer. They do not substitute for a network penetration assessment or an analysis of every resource-exhaustion strategy.

## 12. Collectives and parameter-server semantics

All-reduce, all-gather, reduce-scatter, scatter, gather, broadcast, and point-to-point transfers are implemented through raw socket requests and coordinator routing. The coordinator waits for the required membership, validates operation compatibility, performs the requested array operation, and returns the appropriate result to each rank. All-gather can preserve uneven shard lengths. Reduce-scatter partitions a flattened aggregate using a deterministic quotient-and-remainder layout, including valid empty slices when a tensor is smaller than the process group.

Ordered collective participation is part of the API. Matching names are insufficient if ranks invoke operations in inconsistent orders or with different memberships. A subgroup is an ordered view over global ranks; peer and root identifiers retain their global meaning. This makes topology arithmetic auditable and avoids accidental reinterpretation of a local index as a global peer. Shape and reduction checks precede the calculation, while aggregate limits prevent many individually valid messages from accumulating without a bound.

Coordinator routing is deliberately distinguishable from a bandwidth-optimal ring. The code is executable and its results are tested, but centralized fan-in, fan-out, reduction, copying, and serialization impose a bottleneck. The coordinator also has its own memory footprint. A rank's sharded memory accounting cannot be applied to the server by assumption. Communication measurements on loopback include scheduling and copying effects that differ from a real multi-node accelerator fabric.

The parameter server exposes versioned initialization, pull, and push. A fixed worker set contributes gradients once per version. After every required contribution arrives, the server averages gradients and applies an atomic finite update. Stale pushes are rejected without modifying the current state, and duplicate worker contributions cannot be counted twice. This is synchronous versioned aggregation, not an asynchronous optimizer that compensates for stale gradients. Its consistency contract is explicit so that callers can reason about retry behavior without assuming that a retried push is automatically harmless.

## 13. Three-dimensional parallelism and executable schedules

Ranks use coordinates for data, pipeline, and tensor dimensions, with global rank defined as `(data * pipeline_degree + pipeline) * tensor_degree + tensor`. A data group varies the data coordinate while holding the other two fixed. A pipeline group varies its stage coordinate, and a tensor group varies its tensor coordinate. For a two-by-two-by-two topology, rank five has coordinates one, zero, one; its data partner is rank one, its pipeline partner is rank seven, and its tensor partner is rank four.

The framework validates three-dimensional partitioning on both an analytic MLP and the actual small MLA decoder. The decoder demonstration partitions attention heads and feed-forward hidden features across tensor ranks. Column projections produce local features; row projections sum partial outputs. A custom copy mapping is the identity in forward and all-reduces its backward cotangent. A complementary reduction mapping all-reduces forward partial outputs and passes the already replicated backward cotangent unchanged. Applying an extra sum to that second mapping would multiply gradients by the tensor degree.

Compressed attention projections replicated within a tensor group require special parameter-gradient reductions because each rank contributes a subset of heads. Normalization parameters outside the copy mapping already receive complete cotangents and must not be summed again. The same distinction applies to replicated embeddings and the untied output head in the stage-separated demonstration. These ownership rules are checked by reconstructing every full parameter gradient and comparing it with a dense combined-batch reference.

Pipeline stages send activations forward and input-leaf gradients backward over explicit rank pairs. Microbatches accumulate before the optimizer step, and data groups average equal-mass local gradients. The demonstrated schedule prioritizes correctness over overlap and bubble elimination. It is a fixed small topology, not an automatic arbitrary-size partition planner. Native GPU tensor partitioning, overlapping communication streams, and pipeline scheduling policies beyond the implemented sequence remain separate engineering work. The exported weights and numerical comparison reports identify exactly what executed.

## 14. ZeRO-style state ownership and update lifecycle

The sharded AdamW primitive partitions persistent parameter storage, accumulated gradients, first moments, and second moments across a data group. Every rank validates the same parameter layout and hyperparameter digest before participating. Uneven dimensions are handled explicitly, so a small bias tensor can legitimately contribute an empty local slice. Global names and shapes remain stable while local ownership differs. The optimizer does not retain a permanent full parameter array internally.

Its lifecycle is explicit: materialize a named tensor, perform the operation that requires it, accumulate its full gradient through reduce-scatter, then release the materialized tensor. Only one named tensor may remain materialized through this API at a time. The caller must also discard its references. Releasing an internal pointer cannot free an array that a model graph still retains, and the documentation must not confuse those two ownership domains.

The local gradient shard is accumulated across microbatches. A step computes the global norm from shard contributions, applies consistent clipping, checks all-rank finiteness, and performs the ordinary bias-corrected AdamW equations on owned elements. A nonfinite contribution causes every rank to skip the update. Tests compare uneven three-rank shards with an unsharded reference across several steps, including accumulation and clipping. This establishes the arithmetic of partitioning, rather than inferring correctness merely from similar losses.

For a rank owning `n` elements, the four persistent float32 vectors occupy exactly sixteen times `n` bytes, before array-object overhead. Materialization adds a full tensor, received shard buffers, serialization copies, and possibly a full gradient. The coordinator retains aggregate state during collectives. Direct primitive callers must additionally count their constructor mappings and retained arrays. The automatic ZeroTransformer path avoids a full model mapping by streaming initialization. Its custom embedding, linear, and normalization operators gather one weight for forward and release it immediately. Backward captures activation inputs and a parameter name, then gathers the weight again only for its derivative. A scalar autograd anchor carries parameter dependence without allocating replicated parameter leaves. Weak-reference tests establish that full gathered weights die while the forward graph remains alive.

The complete decoder therefore supports automatic parameter materialization across data ranks. Batched linear gradients contract flattened sample axes directly, avoiding a batch-times-parameter intermediate. Tied embedding lookup and output projection contribute to the same gradient shard. An optimizer mutation generation rejects backward through a stale graph after an update or restore. Saved activations and explicit full parameter gradients still consume memory. Activation checkpointing, overlap, and composition with the separate pipeline/tensor-parallel schedule are not implemented.

Distributed snapshots preserve sharded parameters, gradients, both moments, accumulation counters, and rank-local random state. Every rank durably writes a uniquely named payload and metadata, then participates in preparation acknowledgement. The leader revalidates every shard before replacing the global manifest. Restore validates every destination array and incoming shard before a collective agreement permits mutation. Fresh process groups recover byte-exact continuation in tests. A caller disconnected after manifest publication may be uncertain whether saving succeeded; reading the manifest resolves that ambiguity. Membership changes and checkpoint resharding require different algorithms and are not implied by this protocol.

## 15. Rigorous model-state, cache, and activation accounting

Let the parameter count be `P`, data degree `D`, tensor degree `T`, and pipeline degree `S`. An ideal even partition assigns approximately `P/(D*T*S)` owned elements to each rank, although embeddings, uneven layers, and replicated components cause deviations. The large preset has `P = 7,018,450,944`; one complete float32 parameter copy alone occupies 28,073,803,776 bytes. Ordinary local AdamW additionally retains a master copy, gradients, and two moment arrays, making its principal state about twenty bytes per parameter before other allocations.

The sharded optimizer's four float32 vectors give an ideal persistent term of `16*P/(D*T*S)` bytes. In a two-by-two-by-two scenario this is 14,036,901,888 bytes per rank. A mixed representation with two-byte working weights, four-byte gradients, four-byte master weights, and two four-byte moments has an eighteen-byte ideal term instead. These are accounting assumptions, not observations that NumPy emulation has compressed all arrays to two bytes.

Cache memory depends on layers, batch size, padded token capacity, and stored features. Expanded attention stores content and rotary keys plus values for every head. Latent caching stores compression-rank features plus one rotary key per token. At batch one, sequence length 2,048, thirty-two layers, and two-byte storage, the preset's expanded cache is 1,342,177,280 bytes and its latent cache is 75,497,472 bytes. The actual float32 cache doubles those storage figures; allocator metadata, page tables, and transient attention arrays remain additional.

A pipeline boundary activation of shape batch by time by model width costs 33,554,432 bytes for batch one, length 2,048, width 4,096, and float32. That is not the whole activation budget. Feed-forward intermediates, compressed and reconstructed attention coordinates, normalization inputs, residual paths, retained graphs, and masks add substantially. Several gate-related arrays can each exceed one hundred megabytes in this scenario. The estimator therefore reports boundary storage as a component, never as a total training-memory prediction. Peak memory must include lifetimes and overlapping buffers, not only a sum of persistent model states.

## 16. Hardware topology and interconnect bottlenecks

A concrete simulated placement assigns ranks zero through three to one virtual host and ranks four through seven to another. Each host contains both pipeline stages and both tensor shards for one data replica. Tensor collectives and pipeline transfers are therefore intra-host, while data-parallel synchronization crosses hosts. This placement is a scenario, not the physical topology of the development Mac. Local processes communicate over loopback during testing.

For capacity analysis, the slow link scenario uses 200 gigabits per second, equivalent to 25 gigabytes per second before protocol overhead, and a five-microsecond latency input. An illustrative fast intra-host fabric can be modeled separately at 600 gigabytes per second and one microsecond. These numbers are configurable abstractions resembling different interconnect classes; they are not specifications or benchmarks for a named NVLink or InfiniBand product. Real links have directional limits, topology constraints, switch contention, protocol overhead, and competing traffic.

A hypothetical ring all-reduce over `D` ranks moves approximately `2*(D-1)/D` times the payload per rank, with a latency term proportional to twice `D-1`. The provided estimator applies that analytical formula while separately labeling the actual coordinator implementation. For the large preset with tensor and pipeline degrees two, a float32 gradient payload per such partition is approximately 7.018 gigabytes. Even ideal serialization over the assumed slow link costs roughly 0.281 seconds for the two-rank ring model, before computation or contention.

The coordinator can serialize more traffic and concentrate both memory bandwidth and arithmetic on one process. Concurrent tensor and data reductions can compete for host memory even if their logical groups differ. Pipeline traffic can also delay collectives when network paths share a physical bottleneck. A realistic performance plan must record message-size distributions, collective order, achieved bandwidth, queueing delay, and overlap with computation. Neither loopback runtime nor an analytical line-rate estimate establishes achievable large-model throughput. Those quantities answer different questions and must remain separately labeled in reports.

## 17. Security and alignment auditing protocol

An audit begins with an inventory of assets and trust boundaries: training text, preferences, tokenizer state, model weights, optimizer state, network credentials, checkpoints, and logs. The coordinator and workers are trusted participants in the present design. An attacker controlling a participant with the shared secret can submit authenticated but harmful values; HMAC does not solve that problem. Public deployment requires a stronger admission and isolation design before any model-quality discussion can make the system operationally safe.

Data auditing records source revision, provenance, permitted use, transformations, exclusions, and split assignment. Checks include exact and near duplicates, personally sensitive content, embedded credentials, benchmark contamination, and distribution imbalance. The bundled examples are original fixtures; the framework does not claim to have performed these checks over a global corpus. Every change to filtering or tokenization should produce a new identifiable data version, and held-out evaluation material must remain outside all optimizer stages.

Transport auditing exercises malformed lengths, illegal dtypes, shape-product mismatches, invalid authentication, repeated sequence numbers, duplicate rank claims, missing peers, delayed messages, and aggregate queue exhaustion. State auditing verifies that a rejected operation leaves parameters and versions unchanged. Recovery auditing injects interruption before payload synchronization, before manifest replacement, and after commit. Numeric auditing injects NaNs, infinities, forward precision overflow, and inconsistent collective shapes, then checks that a partial update cannot escape as an accepted step.

Alignment auditing evaluates behavior rather than assuming a preference objective creates safe behavior automatically. It uses held-out prompts for factual accuracy, appropriate uncertainty, refusal boundaries, prompt injection, private-data leakage, and consistency across demographic or linguistic variations relevant to deployment. Pairwise preference gains are reported alongside regressions and confidence intervals. A separate review examines whether chosen responses merely exploit stylistic shortcuts or conceal errors behind confident language. Release decisions require both model evaluations and systems evidence; neither a safety rubric nor a passing unit suite alone authorizes broad deployment.

## 18. Verification strategy, operational acceptance, and limitations

Verification proceeds from local invariants to integrated execution. Kernel tests compare softmax, normalization, rotary transforms, and tiled attention with dense formulations and numerical derivatives. Tensor tests cover broadcasting, repeated indices, shared graphs, deep graphs, and masked rows. Model tests compare full and paged decoding, verify parameter inventories, enforce allocation guards, and exercise cache rollback. Data tests inspect target shifts and boundaries rather than checking only array shapes.

Training tests compare uninterrupted and resumed parameter values, optimizer masters and moments, random state, counters, and logs. They validate unequal-target gradient accumulation and frozen DPO reference persistence. Distributed tests compare reconstructed gradients and updates with independent single-process references, including actual small Transformer execution. Numerical agreement is reported with tolerances and dimensions. The test harness uses small deterministic fixtures so that failures can be investigated without loading a large model or starting unbounded local work.

The local operational layer now includes bounded authenticated HTTP serving, metrics, per-request cache accounting, process supervision, run ownership, and tested multi-rank restart procedures. The HTTP server uses a fixed worker pool and bounded accepted-connection queue, rather than creating a thread for every connection. A strict parser rejects ambiguous framing and oversized input. Generation requires a private bearer token and a loopback destination. Deadlines and disconnects are checked between decode calls, and caches are reclaimed through exception-safe cleanup. No component exposes a public inference endpoint.

The supervisor starts a new process group, forces one BLAS thread, lowers scheduling priority, and bounds wall time and captured output. Cooperative termination lets a local trainer finish its optimizer boundary and checkpoint. An unresponsive child receives process-level termination and then a hard kill after grace expires. The supervisor also cleans descendants when the group leader exits. It is a watchdog for trusted framework commands, not a sandbox for arbitrary generated C++ or an operating-system resident-memory quota.

Operational acceptance for broader deployment still requires sustained load testing, independent security review, authenticated artifact provenance, retention management, and verified behavior on intended tasks. The included C++ evaluation uses held-out original pairs across skill levels and programming domains; response likelihood preferences and bootstrap uncertainty provide a reproducible screening signal, not certification of free-form tutoring. Hardware-specific kernels and transports require their own correctness and performance evidence. Arbitrary topology planning, combined three-dimensional ZeRO scheduling, encrypted multi-node transport, and elastic recovery remain outside this implementation.

The complete source is delivered as ordinary files, with no code sections replaced by placeholders. Mathematical derivations and the architecture manual accompany runnable examples and recorded results. That completeness is a statement about the delivered implementation, not an attempt to rename missing production validation. The framework provides inspectable algorithms and working small-scale orchestration from which further engineering can proceed. Its small randomly initialized checkpoints should not be represented as capable assistants, and its seven-billion-parameter metadata should not be represented as a trained seven-billion-parameter model.
